This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev           # Dev server (port 5173)
npm run build         # Type-check (tsc) + Vite production build
npm run check-types   # tsc --noEmit
npm run test          # Vitest (watch mode by default)
npm run lint          # Biome check (src/ only)
npm run lint:fix      # Biome auto-fix
npm run format        # Biome format --write src
npm run parse-docs    # Regenerate game data JSON from data/docs-en.json
```

Run a single test file: `npx vitest run src/solver/test/somersloops.test.ts`

CI runs `check-types` then `test` (no lint in CI).

## Architecture

### Stack
React 19 + TypeScript + Vite. Mantine v9 (dark theme forced). Zustand for global state. React Flow (`@xyflow/react`) for graph visualization. HiGHS WASM for LP solver. Supabase for auth/database/realtime sync. Biome for linting/formatting. Deployed to GitHub Pages with base path `/satisfactory-logistics/`.

### Path alias
`@/` maps to `src/` (configured in both `tsconfig.json` and `vite.config.ts`).

### Key directories

- **`src/core/`** — Zustand store root (`zustand.ts`), persistence (IndexedDB via `indexedDbStorage`), store migrations, Supabase client, `assetPath()` helper
- **`src/factories/`** — Factory model (inputs/outputs/logistics), factories list UI, charts, factory-level store slice
- **`src/solver/`** — Production solver: LP formulation (`algorithm/`), React Flow graph layout (`layout/`), solver page UI (`page/`), test suite (`test/`)
- **`src/games/`** — Game model (collections of factories), save/load, Supabase sync (`sync/`), save file import (`import/`, `save/`)
- **`src/recipes/`** — Static game data: items, recipes, buildings, schematics (JSON files generated by `parse-docs`), recipe graph utilities
- **`src/tools/`** — Standalone tools: splitter calculator with ratio solver and React Flow visualization
- **`src/auth/`** — Supabase auth, login page, sync manager
- **`src/layout/`** — App shell: header, footer, sticky positioning

### State management
Single Zustand store composed via `withSlices()` helper — each feature has its own slice (`factoriesSlice`, `solversSlice`, `gamesSlice`, `chartsSlice`, etc.). Cross-slice logic uses `withActions()` for actions that span multiple slices. State persists to IndexedDB with versioned migrations in `src/core/migrations/`. The `gameSave` slice is excluded from persistence.

### Solver pipeline
1. User defines factory inputs/outputs → `SolverProductionRequest`
2. `solveProduction()` builds LP constraints (resource flows, recipe ratios, somersloop amplification)
3. HiGHS WASM solves the LP (loaded via `loadHighs()` with base-path-aware WASM location)
4. Solution is converted to React Flow nodes/edges (`getSolutionNodes`)
5. Dagre auto-layout positions the graph

### Game data
Static JSON files (`FactoryItems.json`, `FactoryRecipes.json`, `FactoryBuildings.json`, `FactorySchematics.json`) are generated from Satisfactory game docs via `npm run parse-docs`. Source data lives in `data/docs-en.json`.

### Asset paths
Use `assetPath()` from `@/core/assetPath` for all image/asset `src` attributes. This prepends the Vite base URL, which differs between local dev (`/`) and GitHub Pages (`/satisfactory-logistics/`).

### Supabase Realtime
Game state syncs across tabs/devices via Supabase Realtime Broadcast channels (`game:{savedId}`). Uses last-write-wins with timestamp-based stale rejection and echo suppression via `senderId`.

### Splitter calculator
Located in `src/tools/splitter-calculator/`. Has two solver modes: default (GCD/LCM integer ratios) and alternate decomposition-based solver. State is URL-encoded via `useSearchParams` for shareability. Visualized with React Flow + dagre layout. Splitters always split evenly in-game (50/50 or 33/33/33) — algorithms must never assign unequal rates to a single splitter's outputs.
